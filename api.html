Dimer Class

Definition of a core Dimer (molecule-like) class.

class prop_sapt.molecule.Dimer(geometry, reference='RHF', memory=None, **kwargs)[source]

Bases: sinfinity

Core dimer (molecule-like) class.

Initialises and stores all necessary values for ‘propSAPT’ calculations. Performs SCF calculations for the monomers.

The fragment structure of the geometry (atoms, charges and multiplicities of monomers A and B and of any extra fragments) is in fragments, a prop_sapt.fragments.DimerFragments.

The settings the dimer is built with are kept: psi4_options, the Psi4 options changed from their defaults, and fitting_bases, the fitting basis sets as built (basis.blend()) by option, “DF_BASIS_SCF” and “DF_BASIS_SAPT”. Changing the options afterwards does not change the dimer.

Memory comes from Psi4’s setting (psi4.set_memory), as for any Psi4 calculation.

Parameters:

  • geometry (str) – Dimer geometry in Psi4 format, with monomers A and B as its first two fragments; any further fragments are ghost atoms.

  • reference (str, optional) – “RHF” or “RKS”. Defaults to “RHF”.

  • memory (float | None, optional) – Deprecated, set psi4.set_memory instead. Memory of the JK object in GB; None, the default, follows Psi4’s memory.

Keyword Arguments:

  • functional (str) – Functional of an RKS reference. Defaults to the default_functional option.

  • grac_A (float) – GRAC shift of monomer A (Psi4’s dft_grac_shift). Defaults to no shift.

  • grac_B (float) – GRAC shift of monomer B. Defaults to no shift.

clear_theta_amplitudes()[source]

Free the theta amplitudes of the exchange density matrices, see get_theta_amplitudes. The exchange-dispersion ones are as large as the dispersion amplitudes. calc_densities frees them when it is done; call this after calling calc_density_matrix for both monomers yourself.

use_cpscf_type(cpscf_type: str | None, df_basis: str | None = None) → Iterator[None][source]

Context in which the CPSCF solves of the dimer build their J and K matrices the way cpscf_type says, see the cpscf_type option.

The density matrices and the properties run in this context, with the cpscf_type and df_basis_cpscf options; the SAPT energies do not. Inside, cpscf, cpscf_batch, get_cpscf_ra and get_cpscf_sb use the J/K object of build_cpscf_jk, built on entering and freed on exit. The response amplitudes of get_cpscf_ra and get_cpscf_sb are kept for each type apart, and the theta amplitudes (see get_theta_amplitudes) are freed on entering if they were calculated with another type. A context of the type already in use, e.g. a nested one, keeps its J/K object.

Example

>>> with dimer.use_cpscf_type("DF", "aug-cc-pvqz-jkfit"):
...     x = dimer.cpscf_batch("A", perturbations)
Parameters:

  • cpscf_type (str | None) – “DIRECT” or “DF”, case-insensitive, or None for the monomer SCF’s J/K objects.

  • df_basis (str | None, optional) – Fitting basis of “DF”, ignored by the other types. Defaults to the dimer’s DF_BASIS_SCF fitting basis (see build_cpscf_jk).

Raises:

ValueError – Raised for an invalid cpscf_type or df_basis.

prop_sapt.properties.calc_property(dimer: Dimer, prop: str | ndarray, response: bool | str = True, **kwargs) → DataFrame[source]

Calculation of interaction-induced property.

The property is the field derivative of the energy calc_sapt_energy gives for the same response.

Known issue: the S^inf exchange-dispersion term x2_exch-disp is not yet the field derivative of EXCH-DISP2. For the dipole of He-H2 in aug-cc-pVTZ it is 7.2e-5 a.u. off the finite-field derivative (about 18%), and the total x_induced carries that error. Every term of x_induced_S2 agrees with its finite-field derivative. See “Known limitations” in the usage guide.

Parameters:

  • dimer (Dimer) – A dimer system.

  • prop (str | np.ndarray) – Property to calculate. Either name of already implemented property, e.g. dipole moment (prop=”dipole”) or an array with matrix representation, in AO basis, of the operator corresponding to a property to calculate.

  • response (bool | str, optional) – Induction amplitudes of the second-order induction terms. True: the coupled (CPSCF) ones, x2_ind,r, x2_exch-ind,r_S2 and x2_exch-ind,r (plus the uncoupled x2_ind). False: the uncoupled ones, x2_ind, x2_exch-ind_S2 and x2_exch-ind, with no CPSCF equations solved for them. “both”: both sets. The totals take the coupled terms unless response is False. The monomers relax in the field in every mode, so the other terms do not depend on it. Defaults to True.

Keyword Arguments:

results (str) – Path of the CSV file the results are saved to. Defaults to “results.csv”.

Returns:

DataFrame with results.

Return type:

pd.DataFrame

prop_sapt.properties.perform_property_contractions(dimer: Dimer, property_matrix: ndarray, response: bool | str = True) → DataFrame[source]

Calculates property contributions. Returns pandas.DataFrame with values of separate contributions and the summed-up total.

The property is the field derivative of the energy of calc_sapt_energy with the same response. The monomers relax in the field in every mode (the first-order, dispersion and exchange-dispersion terms do not depend on it); response chooses the induction amplitudes of the second-order induction terms:

  • True: the coupled (CPSCF) ones, x2_ind,r, x2_exch-ind,r_S2 and x2_exch-ind,r. The uncoupled x2_ind is reported too.

  • False: the uncoupled ones, x2_ind, x2_exch-ind_S2 and x2_exch-ind. No CPSCF equations are solved for the induction amplitudes or their derivatives.

  • “both”: both sets.

The totals x_induced and x_induced_S2 take the coupled terms unless response is False, as calc_sapt_energy does.

Parameters:

  • dimer (Dimer) – A dimer system.

  • property_matrix (np.ndarray) – A matrix representation of the operator corresponding to a property to calculate, in AO basis.

  • response (bool | str, optional) – True, False or “both”, see above. Defaults to True.

Returns:

DataFrame with results.

Return type:

pd.DataFrame

Calculate interaction-induced changes in the density matrix of dimer (and both monomers).

The matrices are for one spin (the Da convention): the total density of the closed-shell monomers is twice their sum. Saved matrices are always in the AO basis (transformed from the MO basis if needed); saved cubes hold the total density.

  • save_matrices (bool, optional) – Whether to save density matrices. Defaults to False.

  • matrices_dir (str, optional) – Directory to save density matrices. Defaults to “.”.

The defect is the largest element of

Delta[mu,nu] = sum_q w_q (sum_X w_X(r_q) - 1) phi_mu(r_q) phi_nu(r_q),

the difference between the sum of the fragments’ weighted-overlap matrices and the overlap matrix on the same grid. prop_sapt.sapt_driver.calc_sapt_energy(dimer: Dimer, **kwargs) → Series[source]

Calculate SAPT energy for a given dimer.

This function computes the SAPT energy components for a dimer system: SAPT0 for an RHF reference, SAPT(DFT) for an RKS one. The dispersion is the uncoupled one in both cases. With RHF that is the SAPT0 dispersion. With RKS it is not the coupled dispersion that Psi4’s SAPT(DFT) uses by default, so SAPT(DFT) dispersion and total energies differ from Psi4’s. Coupled dispersion is not implemented. The results are returned as a pandas Series and, unless results=False, saved to a CSV file, “sapt_results.csv” by default.

The SAPT energy components are calculated as follows:

  • ELST1: First-order electrostatic energy

  • EXCH1: First-order exchange energy

  • EXCH1(S^2): First-order exchange energy with S^2 correction

  • IND2,R: Second-order induction energy (response)

  • EXCH-IND2,R: Exchange-induction energy (response)

  • DISP2: Second-order dispersion energy

  • EXCH-DISP2: Exchange-dispersion energy

Run Configuration

Run configuration for the propSAPT runner (prop-sapt run).

A run is described by a small YAML or JSON file. Every key is optional except tasks:

reference: RHF                # "RHF" or "RKS"
functional: pbe0              # RKS only; defaults to the `default_functional` option
grac: {A: 0.0851, B: 0.0999}  # RKS only, GRAC shifts in Hartree

basis: aug-cc-pvtz
df_basis: aug-cc-pvtz         # stem: DF_BASIS_SCF = <stem>-jkfit, DF_BASIS_SAPT = <stem>-ri
df_basis_scf: null            # full basis names, taking precedence over the stem
df_basis_sapt: null
basis_overrides: basis_overrides.json   # path, or inline {element: {basis_key: basis}}
basis_dirs: [basis]           # extra directories searched for <basis name>.gbs files

memory: 2                     # in GB, or a string such as "2 GB" or "500 MB"
threads: 2

psi4_options: {scf_type: direct, e_convergence: 1.0e-10}
propsapt_options: {r_convergence: 1.0e-10}

output:
  dir: "."                    # "{geometry}" expands to the geometry file stem
  psi4_output: null           # defaults to output_hf.dat / output_propsapt_dft_<functional>.dat

tasks:                        # true for defaults, a mapping to change them
  monomer_references: {cubes: true, fchk: true}
  sapt_energy: {results: sapt_results.csv, response: true}
  property: {prop: dipole, results: property_results.csv, response: true}
  densities: {orbital_basis: AO, save_cubes: true, save_matrices: true,
              matrix_format: npz}

Values are taken from the built-in defaults, then the file, then the command-line flags. A –df-basis flag sets both fitting bases from its stem, replacing df_basis_scf and df_basis_sapt given in the file.

DF_BASIS_SAPT is always set: from df_basis_sapt, else <df_basis>-ri, else <basis>-ri. DF_BASIS_SCF is set from df_basis_scf, else <df_basis>-jkfit; with neither given it is left to Psi4, which picks <basis>-jkfit where that exists and a universal JKFIT basis otherwise (e.g. for He with aug-cc-pvtz). The densities task saves its matrices into one self-describing bundle, densities.npz (matrix_format: npz, read with prop_sapt.load_densities), or as bare .npy files (matrix_format: npy, deprecated). The older compress_matrices: true/false setting still works, as npz/npy, with a deprecation warning.

Relative paths inside the file (basis_overrides, basis_dirs) are resolved against the directory of the file; the output directory is resolved against the current working directory.

Basis sets missing from Psi4’s library can be added as Psi4-format files named <basis name>.gbs in one of the basis_dirs, e.g. written from ccRepo or the Basis Set Exchange with prop-sapt basis fetch (see prop_sapt.basis_fetch).

Basis Set Overrides

Per-element basis set overrides.

Some elements lack the auxiliary basis sets that pair with the orbital basis in Psi4 (e.g. aug-cc-pvtz has no -jkfit / -ri set for Zn). For those elements another basis is substituted, leaving every other element on the default. Overrides are given element-first, as a mapping or as a JSON file holding one:

{
    "Zn": {"DF_BASIS_SCF": "def2-tzvpd-ri", "DF_BASIS_SAPT": "def2-tzvpd-ri"}
}

where each key under an element is a Psi4 basis option (“BASIS”, “DF_BASIS_SCF”, “DF_BASIS_SAPT”, …). An override is applied only for a basis option that the calculation sets, so one file can serve several kinds of calculation: entries for options the calculation does not use (e.g. “DF_BASIS_MP2” in a propSAPT run) are skipped.

Fetching Basis Sets

Fetch basis sets missing from Psi4’s library into Psi4-format files (prop-sapt basis fetch).

The files are written once, e.g. on a workstation or login node, into a directory that runs then list in basis_dirs (see prop_sapt.config), so calculations read fixed inputs and need no network or extra packages. Two sources are available, each through an optional package that is installed separately and only where this command is used:

ccrepo ccRepo, http://www.grant-hill.group.shef.ac.uk/ccrepo/, through ccrepo_utility

(its dependencies are not installed with it, so they are listed as well): pip install git+https://github.com/Sheffield-Theoretical-Chemistry/ccrepo_utility colorlog tqdm requests

bse Basis Set Exchange, https://www.basissetexchange.org, through basis_set_exchange:

pip install basis_set_exchange

Each file is named after its basis set, by default “<source>-<basis set>”, e.g. “ccrepo-aug-cc-pVTZ_MP2FIT” in ccrepo-aug-cc-pvtz_mp2fit.gbs. A file must not take the name of a basis set in Psi4’s library: Psi4 reads the first file of a name it finds, so a file holding a few elements would hide the library basis set for every other element.

Fragment Populations

Fragment population operators: weighted-overlap matrices of a partition of space.

Given a molecular quadrature grid (points r_q, weights w_q) and fragment weights w_X(r_q) at its points, the weighted-overlap matrix of fragment X is

W_X[mu,nu] = sum_q w_q w_X(r_q) phi_mu(r_q) phi_nu(r_q),

computed once per geometry. The number of electrons any AO density matrix D puts on fragment X is then a trace, Tr(D W_X), with no further grid work. The first-moment matrices (r_q times the same weights) give fragment dipoles in the same way.

Points are in bohr. Matrices are in the AO basis of the given Psi4 basis set, in Psi4 AO order, and no spin factor is applied, as in prop_sapt.evaluate: the density matrices of calc_densities follow the Da convention, pass 2 * D for the total (RHF) density.

Fragment weights come from any partitioning: the Becke partition of Psi4’s molecular grid (becke_fragment_weights), Hirshfeld-like weights from the monomer densities (hirshfeld_fragment_weights), or weights computed elsewhere, e.g. LISA or MBIS weights from horton_part on its own grid, passed as arrays with that grid’s points and weights.

prop_sapt.forces.calc_force_at_nuc(mol: Molecule, rho: ndarray | Sequence[ndarray], atidx: int, add_nuclear: bool = True, **kwargs) → ndarray | list[ndarray][source]

Computes the Hellmann-Feynman force on nucleus atidx from one or more electron density matrices.

The electronic contribution is evaluated analytically via the electric field integrals at the nuclear position: F_i = Z_A * Tr[rho * <mu|(r_i - R_Ai)/|r - R_A|^3|nu>]. The nuclear-nuclear repulsion is added by default.

Accepts a single density matrix or a sequence of density matrices. When a sequence is provided, the electric field integrals are computed only once and reused for all matrices.

Parameters:

  • mol (psi4.core.Molecule) – Psi4 molecule defining the geometry and nuclear charges.

  • rho (np.ndarray | Sequence[np.ndarray]) – One-particle density matrix in the AO basis, shape (nbf, nbf), or a sequence of such matrices.

  • atidx (int) – Zero-based index of the nucleus on which the force is computed.

  • add_nuclear (bool, optional) – If True, adds the nuclear-nuclear repulsion force. Set to False to obtain the electronic contribution only. Defaults to True.

  • **kwargs – Accepts basisset (psi4.core.BasisSet) to reuse a pre-built basis set instead of constructing one from the molecule.

Raises:

  • ValueError – If rho is an empty sequence.

  • TypeError – If mol is not a psi4.core.Molecule.

Returns:

Force vector of shape (3,) in atomic units (Hartree/Bohr)

when a single density matrix is given; a list of such vectors when a sequence is given.

Return type:

np.ndarray | list[np.ndarray]

prop_sapt.forces.calc_force_nuc_nuc(mol: Molecule, atidx: int) → ndarray[source]

Computes the nuclear-nuclear repulsion force on nucleus atidx from all other nuclei.

Uses Coulomb’s law: F_a = sum_{b != a} Z_a * Z_b * (R_a - R_b) / |R_a - R_b|^3.

Parameters:

  • mol (psi4.core.Molecule) – Psi4 molecule defining the geometry and nuclear charges.

  • atidx (int) – Zero-based index of the nucleus on which the force is computed.

Returns:

Nuclear-nuclear force vector of shape (3,) in atomic units (Hartree/Bohr).

Return type:

np.ndarray
